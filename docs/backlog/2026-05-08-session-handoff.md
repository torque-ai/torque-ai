## Memory notes worth preserving

(For when you pick up next week — these are auto-loaded so you don't need to remember.)

- Test contamination via require.cache injection: `vi.resetModules()` does NOT clear manually-injected `require.cache[modulePath]` entries. Tests that do `require.cache[X] = mock` must also clear them in cleanup.
- DI singleton container caching: `defaultContainer` is a module-level singleton in `server/container.js`. Its `_instances` map persists across `vi.resetModules` since the container module itself isn't deleted. Tests that need a fresh container must explicitly `delete require.cache[require.resolve('../container')]`.
- task-manager.js stub-registration pattern: gates registrations behind `if (!has('X'))`. Tests that pre-register a mocked X *before* requiring task-manager get their mock kept; tests that override after task-manager loads need `container.override` on a freshly-booted instance.
